旧的那个站是拿手写 HTML 堆起来的。好处是全部可控，坏处是每加一篇文章都要手动补列表、补归档、补 RSS，补到第三十篇就彻底不想写了。

这次重建只定两条规矩：**发文章不能超过一分钟操作**，**改布局不能去翻内容文件**。

## 为什么不是 WordPress

我确实考虑过。它的后台是现成的，插件生态也全，但有两个绕不开的问题：

- 需要一台一直在线的服务器，还要有人维护数据库和 PHP；
- 我真正需要的东西——静态托管、Git 版本、免费 HTTPS——它都有更适合的替代。

Hexo 和 Hugo 也在候选里。Hugo 构建快得离谱，Hexo 的中文主题漂亮，但它们都共享同一个麻烦：**主题改了样式，你要么改主题源码，要么写一层自定义 CSS 盖上去**，升级一次主题就可能全崩。

Astro 吸引我的点很朴素：内容就是 Markdown，页面就是一个 `.astro` 文件，改样式直接改那个文件，没有"主题"这层中间商。

## 三条链路

站点现在的结构足够简单，三条链路互不干扰：

| 要做的事 | 动哪里 |
| --- | --- |
| 发一篇文章 | `src/content/posts/` 加一个 `.md` |
| 加一个资源 | `src/content/resources/` 加一个 `.md` |
| 调整布局 | `src/config/site.json`，或改 `src/layouts/` |

发布流程是这样：

```bash
git add -A
git commit -m "post: 重开一个站"
git push
```

推上去之后 GitHub Actions 会自动构建，大约一分半能看到线上更新。本地也可以先跑 `npm run dev` 预览，端口 4321。

## 关于资源区

之前的资料都散在网盘里，链接发出去三个月就失效一半，我自己也记不清哪个还能用。所以这次给资源单开了一个数据模型：

```yaml
platform: baidu      # 网盘类型
url: https://pan.baidu.com/s/xxxx
code: 8x2k           # 提取码单独一个字段
status: ok           # ok / pending / dead
updated: 2026-11-12
```

提取码和链接分开存，前台就是两个按钮，复制的时候不会把「链接+码」糊成一串。失效了把 `status` 改成 `dead`，卡片会变灰但仍然留着记录，方便回头补。

> 只放自己整理的或者明确授权的东西。这一条不打算松口。
