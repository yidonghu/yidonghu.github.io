# POS 单店本地收银系统

一套跑在**店内一台 Windows 电脑**上的收银系统：PC 管理后台 + 手机/自助收银机网页收银台，数据只写本机一个 SQLite 文件，**全程不依赖互联网，断网照常收银**。

- 后端：Spring Boot 3.3.5 + JdbcTemplate + SQLite（单文件、WAL）
- 前端：原生 HTML/CSS/JS，**免构建**，改完刷新即生效
- 身份：不设店员账号、不做会员，改由「设备」承担身份（自定义名字 + 本地保存 UUID）
- 交付：`打包绿色版.bat` 一键出免安装绿色包（内置精简 JRE）

```
目录：快速开始 · 目录结构 · 手机端与 HTTPS · 扫码 · 功能 · 数据与备份 · 初始化 · CSV · 绿色版 · 常驻运行 · 接口 · 实现要点 · 常见问题 · 已知限制
```

## 快速开始

### 方式一：绿色版（目标电脑没有 Java 也行）

1. 项目根执行 `打包绿色版.bat`，得到 `dist\POS收银绿色版\` 与 `dist\POS收银绿色版.zip`
2. 解压到任意目录（别放 C 盘系统目录），双击 `启动.bat`
3. 浏览器自动打开 `http://localhost:8080`

### 方式二：源码运行（需 JDK 17 + Maven）

```bat
build.bat                 :: 编译出 backend\target\pos.jar
start.bat                 :: 启动服务并自动打开浏览器
```

首次登录后台用默认密码 **admin888**，登录后到「设置」页改掉。

手机接入：手机连同一 Wi-Fi，扫后台「设置」页或入口页 `/` 上的二维码（编的是 https 地址），首次进入给设备起个名字即可收银。

> 端口被防火墙拦时，右键 `放行防火墙端口.bat` →「以管理员身份运行」（放行 TCP 8080 / 8443）。
> 需要开机自启：右键 `安装开机自启.bat` →「以管理员身份运行」，创建计划任务 `POS-Server`。
> 局域网域名、H3C 路由器固定 IP、安卓 DNS 见 [`docs/网络与域名配置.md`](docs/网络与域名配置.md)。

## 手机端与 HTTPS（摄像头扫码必读）

| 地址                           | 端口 | 场景                         | 能否用摄像头                         |
| ------------------------------ | ---- | ---------------------------- | ------------------------------------ |
| `http://本机IP:8080/pos`     | 8080 | 电脑浏览器、扫码枪、手输条码 | 安卓下**不能**（非安全上下文） |
| `https://本机IP:8443/pos`    | 8443 | 手机、自助收银机             | **可以**                       |
| `https://localhost:8443/pos` | 8443 | 主机本机访问                 | 可以                                 |

- 证书是启动时自动生成的自签证书：`data/tls.p12`（密码 `pos-local`，别名 `pos`，10 年有效），SAN 自动写入 `localhost`、`pos.home.arpa`、`127.0.0.1` 与当前所有局域网 IP；主机 IP 变了会自动重签。
- 手机首次打开 https 会提示「连接不是私密连接」：点「高级 → 继续前往」。系统完全离线、没有公共 CA，这是自签证书的正常现象。
- 安卓 Chrome 在 http 页面拿不到摄像头（`navigator.mediaDevices` 为 `undefined`）；收银台检测到会提示改用 https，并保留手输条码。

## 扫码

三条通道，互相兜底：

| 通道        | 适用                  | 说明                                                                            |
| ----------- | --------------------- | ------------------------------------------------------------------------------- |
| 扫码枪      | 电脑 / 收银主机       | USB HID 键盘楔入型，免驱，扫完自动入车（建议枪体设 UTF-8 + 结尾回车）           |
| 摄像头      | 手机、自助机（https） | 有 `BarcodeDetector` 先用原生；没有或解码服务不可用，自动降级到内置离线 ZXing |
| 相册 / 手输 | 全部                  | 拍照识别图片里的码；或直接输入条码回车                                          |

支持格式：EAN-13、EAN-8、UPC-A、UPC-E、Code 128、Code 39、Code 93、ITF、QR。

扫码弹窗只保留一个取景区：一行状态（`把条码放进框里` → `正在识别… 已取 N 帧`）+「相册识别」+ 手输框。后台「新增 / 编辑商品」的条码框旁也有 **「扫码」** 按钮，解出的码自动追加进逗号分隔的条码列表（重复不叠加）。

## 功能

### 收银台 `/pos`（无需登录）

- 商品网格、分类筛选、名称 / 条码搜索
- 购物车折叠态：底栏显示「合计 + 共 N 件 · 查看明细 ▲」，点即展开单品明细（数量增减、单品优惠、挂单/取单）
- 整单折扣、抹零、挂单 / 取单
- 结算：现金（自动算找零，含 10/20/50/100 快捷键与「整付」）、微信、支付宝、银行卡、**组合支付**
- 小票预览与打印（58 / 80mm，走浏览器打印）
- 交接班：开班填备用金，交班自动算应有现金与差额
- 断网提示：主机连不上时顶栏变红显示「离线」，商品走本地缓存仍可浏览

### 管理后台 `/admin`（管理员密码）

| 模块   | 能力                                                                                                            |
| ------ | --------------------------------------------------------------------------------------------------------------- |
| 工作台 | 今日营业额 / 订单 / 客单价、7 日趋势、支付占比、库存预警                                                        |
| 商品   | 一品多码、分类、进价售价、预警值、CSV 导入导出、条码框旁扫码、行内删除                                          |
| 库存   | 入库 / 出库 / 报损 / 盘点、库存流水、成本统计                                                                   |
| 订单   | 明细、重打小票、整单退货（红冲）                                                                                |
| 设备   | 改名、6 位设备码、权限开关（改价 / 退货 / 库存 / 折扣上限）、停用                                               |
| 报表   | 支付方式、设备排行、热销 TOP10、每日汇总，3 种 CSV 导出                                                         |

后台页面可直达收藏：`/admin#products`、`#inventory`、`#orders`、`#devices`、`#reports`、`#settings`。

## 数据与备份

- 数据库：`data/pos.db`（WAL，另有 `-wal` / `-shm`；可用环境变量 `POS_DB` 指定别的路径）
- 金额全部以「分」存整数，不出现浮点误差
- 库存只记流水（`inventory_movement`），任何变动可追溯
- **备份**：后台「设置 → 下载备份」或 `GET /api/admin/backup`，服务端用 `VACUUM INTO` 生成一致性快照。**不要直接复制 `pos.db`**，WAL 未合并会拿到残库
- **恢复**：上传 `.db` → 校验 SQLite 头 → 暂存 `pos.db.pending` → 重启服务后自动替换（旧库保留为 `pos.db.bak-时间戳`）
- 建议每天收盘备份一次，拷到 U 盘或另一台电脑

### 初始化 / 清空数据

后台「设置 → 初始化 / 清空数据」（接口 `GET /api/admin/system/stats`、`POST /api/admin/system/reset?demo=true|false`）：

| 操作               | 行为                                                                                                           | 边界                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 刷新统计           | 读商品 / 分类 / 订单 / 设备 / 库存流水 / 挂单 / 交接班条数与库大小                                             | 不改数据                 |
| 清空所有数据       | 先 `VACUUM INTO backup/pos-before-reset-<时间>-毫秒.db`，再清空全部业务表、重置设置默认值、重建 3 个默认分类 | 管理员密码保留，备份不删 |
| 清空并写入演示商品 | 同上，另写 6 个演示商品（`6900000000001`~`006`，`demo=1`）                                               | 同上                     |

两个按钮都有二次确认，执行中按钮置灰。备份名带毫秒，连续两次重置不会因文件名冲突失败。

## CSV 导入导出

表头顺序不限，缺列按空处理，编码 UTF-8：

| 名称           | 分类 | 条码          | 单位 | 进价 | 售价 | 库存 | 预警值 |
| -------------- | ---- | ------------- | ---- | ---- | ---- | ---- | ------ |
| 农夫山泉 550ml | 饮料 | 6900000000001 | 件   | 2.00 | 2.50 | 50   | 5      |

- 价格单位是**元**，可带两位小数
- 条码已存在则更新该商品，否则新建；分类不存在会自动创建
- 导出时条码写成 `="6901209279126"`，防止 Excel 转成 `6.02E+12`；再导入会剥掉 `="` 包裹、前导单引号，并把科学计数法还原成整数串（位数已丢的只能重新录一次，导入结果里会提示核对）
- 条码全局唯一：同一商品的重复条码自动去重；某条码换到新商品时，会自动从旧商品解绑；启动时清理库里的重复条码与孤儿条码

- 换端口：`jre\bin\java.exe -jar pos.jar --server.port=8081`（8443 固定，被占用会导致启动失败）

## 实现要点

- **结算事务**：订单 + 明细 + 支付 + 库存流水 + 库存快照一次提交，失败全回滚
- **退货**：生成负数红冲单与原路负数支付，库存回补，报表按净额统计
- **设备身份**：浏览器生成 UUID，localStorage + IndexedDB 双份保存，请求头 `X-Device-Id` 上报；后台改名、发 6 位设备码，用于跨浏览器认回同一台机器
- **后台鉴权**：登录换随机 token 存库，`X-Admin-Token` 校验，12 小时过期
- **HTTPS**：8080 之外附加 8443 连接器；启动时 BouncyCastle 生成自签 X.509，SAN 写入全部局域网 IP，IP 变化自动重签，Tomcat 通过 `SSLHostConfig + SSLHostConfigCertificate` 挂载
- **扫码降级**：优先 `BarcodeDetector`，但启动时先调用一次 `detect()` 探测——设备只暴露接口没有解码服务时会抛 `Barcode detection service unavailable`，此时立刻置空 detector 落到 ZXing（运行时再报同类错误同样降级），避免每帧空转永不识别
- **ZXing 用法**：不用库自带 `decodeFromVideoElement`（hint 少、整帧高分辨率，手机几乎识别不到），改为自行 `drawImage` 抓帧 → `HTMLCanvasElementLuminanceSource` → `HybridBinarizer` → `MultiFormatReader.decode`，开 `TRY_HARDER` 并限定上述 9 种格式；先解中间取景框、再整帧兜底、每 6 帧做一次 1500px + 旋转 90/270 的深度尝试
- **商品删除**：先查 `order_item`，没卖过的物理删除（连带条码、库存快照），卖过的只下架，保证历史订单与报表还能读到商品名
- **数据表**：`admin`、`settings`、`device`、`category`、`product`、`product_barcode`、`stock`、`inventory_movement`、`orders`、`order_item`、`payment`、`shift`、`held`、`seq`、`op_log`、`schema_version`

## 常见问题

**手机打不开页面**

1. 手机与主机在同一 Wi-Fi（别连访客网络）
2. `ipconfig` 看主机 IPv4，替换掉 `localhost`
3. 管理员运行 `放行防火墙端口.bat`
4. 主机睡眠会断连，电源设置改成「从不」

**摄像头扫码用不了**

1. 必须走 `https://本机IP:8443/pos`，http 的 8080 在安卓下被安全策略拦住
2. 首次打开 https 要点「继续前往」信任自签证书，否则摄像头与接口都可能被拦
3. 安卓 Chrome 的「私人 DNS / 安全 DNS」别指向不存在的域名，否则整个局域网地址都解析失败
4. 之前拒绝过摄像头权限：到「网站设置 → 摄像头」改回允许

**能看到画面但一直不识别**

- 帧数不涨：摄像头没真正出画，先查是不是 https、权限是否放行
- 帧数在涨却没结果：条码没进中间取景框（退到 15~25cm，让条码横向铺满框）；光线太暗或反光；条码褶皱、贴膜反光、曲面瓶身变形；店内自编码不是标准码时校验位对不上，改用扫码枪或手输
- 实在扫不出：弹窗输入框直接手输条码，回车入车

**`start.bat` 报「'本机:' 不是内部或外部命令」**

- 旧版脚本是 UTF-8 **带 BOM**，BOM 让首行 `@echo off` 失效。当前版本已重写为 UTF-8 无 BOM + CRLF
- 用记事本改过 `.bat` 后另存为「UTF-8（无 BOM）」，或 PowerShell：`[IO.File]::WriteAllText($p,$txt,(New-Object Text.UTF8Encoding $false))`

**重复启动提示端口占用**

- 服务已在跑（可能是 `start-service.bat` 或计划任务起的）。直接访问 `http://localhost:8080`；要重启先 `停止服务.bat`
- 8443 固定端口：同时起第二个实例会因端口冲突导致整个应用启动失败，先停旧的

**扫码枪没反应 / 乱码**

- 需为键盘楔入（HID）型，光标在收银页直接扫
- 乱码时把枪的输出编码设为 UTF-8、结尾字符设为回车

**打印小票**

- 浏览器打印里选小票打印机，边距「无」，缩放 100%；或在设置里开「收款后自动打印」

**换电脑 / 重装**

- 整个目录拷走（至少 `backend/target/pos.jar`、`web/`、`data/`），或只拷 `data/pos.db`
- 用绿色版则整个文件夹拷走即可

**改端口**

- 环境变量 `SERVER_PORT=8090`，或改 `backend/src/main/resources/application.yml`

**多台收银机同时用会不会冲突**

- 所有写操作走同一服务进程与事务，库存不会打架；SQLite 单写连接足以支撑 5 台终端

## 已知限制

- **单店、单主机**：设计目标是一台电脑服务店内多终端；多门店 / 多机汇总不在范围内（v1 多门店草案见 `docs/archive/`，未实现）
- **不做会员与店员账号**：身份由设备承担，没有收银员提成、会员储值、积分
- **打印依赖浏览器**：没有内置 ESC/POS 驱动，小票靠浏览器打印对话框
- **自签证书**：每台新手机首次访问都要点一次「继续前往」，也没有公共 CA 签发的可信证书
- **HTTPS 端口固定 8443**：改端口需改 `TlsConfig`，被占用会导致启动失败
- **无云端同步**：数据只在本机，异地备份靠手动拷文件
